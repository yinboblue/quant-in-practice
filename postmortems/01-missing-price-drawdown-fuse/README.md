# Risk Guard Demo: 缺失数据如何骗过风控

← 返回《量化实操》系列总览：[../../../README.md](../../../README.md)

一个最小可复现项目，演示一类隐蔽的工程事故：

> **"查不到价格"被当成"价格为 0"，导致风控在账户没有真实亏损时判定回撤 -15.7%，并自动执行了砍仓。**

本仓库是这篇复盘文章的配套代码：
**《我的模拟盘没亏钱，风控却判定回撤 -15.7%，还自动砍了半仓》**

代码经过脱敏与通用化：不依赖任何特定市场、数据源或策略逻辑，只用标准库（`sqlite3`，零第三方依赖）。

---

## 事故一句话

同一个组合，系统里存在两本账：

| 用途 | 用的价格口径 | 算出的总资产 |
|---|---|---|
| 每日净值 / 历史峰值 | **全量盯市**（含退市/停牌品种的最后有效价） | ≈ 194,900 |
| 回撤熔断检查 | **当日可交易池**（不可交易品种被剔除，查价缺失） | 168,994 |

持仓中有 6 只品种不在"可交易池"里（临期/公告强赎），风控估值函数遍历到它们时 `continue` 跳过，
约 2.5 万元市值被当作 0：

```
回撤 = 168,994 / 200,500 - 1 = -15.7%   # 风控视角，击穿 -8% 熔断线
真实回撤 ≈ -3%                            # 记账视角，离熔断线很远
```

**分子（当前资产）用过滤池口径，分母（历史峰值）用全量盯市口径 —— 口径不一致就是 bug 本体。**

## 快速运行

需要 Python 3.9+，无需安装任何依赖：

```bash
# 事故复现：错误口径 vs 修复口径
python scripts/reproduce_incident.py

# 单元测试
python -m unittest discover -s tests -v
```

## 目录结构

```
riskguard/
  valuation.py   # 持仓估值：错误写法（缺失计0）与正确写法（最后有效价/成本兜底）
  fuse.py        # 回撤熔断状态机：新触发才执行砍仓，持续触发只更新状态
  snapshots.py   # 全量快照取数：只取最新分区 vs 按实体取末值（ROW_NUMBER）
scripts/
  reproduce_incident.py  # 端到端复现，数字对齐真实事故
tests/             # 三个模块的单元测试
```

## 三条可迁移的教训

1. **缺失值必须显式建模。** `None / NaN / 查不到` 的语义是"我不知道"，正确动作是保守估计 + 告警，而不是静默按 0 处理。按 0 是乐观的静默错误——不抛异常，却污染下游所有决策。
2. **同一数据服务不同决策时，按决策分别取数。** "能不能买"（可交易过滤）和"持仓值多少"（盯市估值）必须是两张表。
3. **周期性全量快照表不能只取最新分区。** 实体会退市/删除/移出，只看最新分区会让消失实体的历史属性全部丢失；应按实体主键取它的末值。

## 防复发机制（超出本 demo 范围，文章第六节详述）

- 数据**覆盖率门禁**：不只检查任务成败，还检查当日行数 vs 近 20 日中位数
- **口径一致性断言**：风控估值与记账估值每日自动比对
- 禁止"把异常改成静默退出"而不补监控告警
- 用**故障注入**（全停/半残/陈旧）验证监控本身有效
- 风控改动必须能**历史重放**验证后才上生产
